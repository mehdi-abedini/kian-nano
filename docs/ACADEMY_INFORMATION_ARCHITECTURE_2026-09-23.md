# Academy Information Architecture

## Objective

Build a durable knowledge architecture that can grow from a company Academy into a searchable scientific intelligence layer.

## Content model

Every article should carry:
- content_type
- domain
- language
- evidence_level
- review_status
- author
- published_at
- updated_at
- references
- related_projects
- related_technologies
- tags
## Evidence levels

Use descriptive epistemic states rather than a numeric quality score:

- Observed / documented
- Established knowledge
- Evidence-supported interpretation
- Working hypothesis
- Forward-looking concept

These states describe epistemic status and are not a universal scientific quality ranking.

## Discovery

Support full-text search, domain filters, content-type filters, evidence-status filters, language filtering, date filtering, and related-content navigation.
## Editorial workflow

Discovery → Draft → Evidence Check → Technical Review → Human Approval → Publish → Monitor → Supersede

The Research Agent prepares drafts and evidence maps. The Website Agent prepares the presentation layer. Publication remains approval-gated.

## Relationship model

Articles may link to:
- research projects
- technologies/products
- patents/IP records
- datasets
- methods
- other articles
- authors

This turns the Academy into a knowledge-graph surface rather than a chronological blog.
## Future agent interfaces

Leave room for:
- semantic search
- citation-aware retrieval
- research-agent reading paths
- "show evidence" views
- project-to-publication navigation
- bilingual content pairing

The Academy should remain useful even when AI features are disabled; AI should enrich the information architecture rather than become its only interface.
