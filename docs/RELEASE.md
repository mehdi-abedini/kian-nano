# Release Procedure

1. Review repository contents for secrets and private information.
2. Run the evaluation prompts.
3. Validate SKILL.md frontmatter and references.
4. Review third-party dependencies and licenses.
5. Commit with a versioned release message.
6. Create a GitHub release and tag after the repository exists.
7. Update the website link to the canonical repository.
8. Record the release hash in the deployment report.

## Distribution rule
The public package contains reusable workflow logic only. Company-specific knowledge remains private.
