# Kian Nano Karno Design Contract

**Status:** v0.1 — architecture baseline

## 1. Core principle

**External references are evidence, not identity.**

External systems may be studied for mechanisms, accessibility practices, information architecture, component behavior, or implementation techniques. Their visual signatures must not be copied into Kian Nano Karno.

The Kian Nano Karno fingerprint is generated from its scientific mission, industrial R&D identity, translational orientation, nanotechnology/materials heritage, biomedical engineering work, and technology-commercialization path.
## 2. Architecture position

External Design Intelligence
→ Research Agent
→ Evidence / Provenance Layer
→ KKN Design Intelligence
→ KKN Design System
→ KKN Design Contract
→ DESIGN.md
→ Design Agent
→ Figma / Code / Elementor
→ Website Agent

DESIGN.md is an agent-readable implementation contract, not the complete brand strategy.

## 3. Non-negotiable invariants

1. KKN identity is authored internally.
2. External references are provenance-tagged.
3. Reverse-engineered visual data is never treated as first-party truth.
4. Design changes are versioned and auditable.
5. Accessibility, responsive behavior, performance, SEO, RTL/LTR, and scientific-content readability are first-class constraints.
6. Production website changes remain human-approval gated.
7. Confidential scientific/IP knowledge never enters public design artifacts.
8. Design recommendations label evidence, inference, experiment, or provisional status.
9. Provider/model selection remains capability-first and task-specific.
10. Periodic rescanning must not create automatic visual drift.

## 4. Design intelligence object

Every external reference should preserve:
- source_id
- source_type
- organization
- source_url
- retrieved_at
- version_or_commit
- license
- visual_scope
- extracted_tokens
- interaction_patterns
- accessibility_notes
- responsive_notes
- provenance_confidence
- relevance_to_kkn
- adoption_status
- rationale
- contradictions
- review_due
## 5. KKN fingerprint dimensions

### Scientific precision
Communicate technical credibility without becoming a sterile laboratory dashboard.

### Translational engineering
Make research → mechanism → prototype → validation → deployment a coherent progression.

### Material intelligence
Nanomaterials, interfaces, molecular structures, instrumentation, and process systems may inform visual metaphors, but literal stock imagery is not mandatory.

### Evidence discipline
References, dates, methods, uncertainty, and validation status should be visually legible where content requires them.

### Industrial seriousness
Industrial R&D, scale-up, process engineering, energy, and commercialization require clarity and restrained visual effects.
### Human expertise
Researchers, engineers, and collaborators remain visible as authors and decision-makers rather than being hidden behind AI-generated surfaces.

## 6. Design-agent behavior

Before generating or editing UI, the Design Agent must:
1. Read this contract.
2. Read design/DESIGN.md.
3. Inspect approved external references.
4. Check provenance and recency.
5. Select principles rather than visual clones.
6. Explain materially new design decisions.
7. Validate tokens, responsive behavior, accessibility, and content hierarchy.
8. Produce a reversible proposal before production mutation.

## 7. Approval gates

RESEARCHED → PROPOSED → DESIGN-VALIDATED → IMPLEMENTATION-READY → HUMAN-APPROVED → PUBLISHED

Only HUMAN-APPROVED may cross the production website boundary.
